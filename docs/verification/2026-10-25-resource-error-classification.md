# 资源下载失败不等于 Surge 控制器不可达

2026-10-25，Surge Mac 6.10.0（12500），合成回环节点资源维护测试。

## 复现证据

在固定测试配置中，已载入合成 A/B/C，选中 C。仅停止合成资源监听器，再对已核对的唯一资源 key 调用一次 `external-resource update <key>`。命令退出 **0**，脱敏 stdout 为：

```text
<resource-key>: 无法连接服务器。 (NSURLErrorDomain:-1004) [未能完成操作。（kCFErrorDomainCFNetwork错误-1004。） (kCFErrorDomainCFNetwork:-1004)]
```

随后 Surge 仍响应状态、组成员及选择查询；资源 ready=true 且 error 非空，旧 A/B/C 和 C 选择保留；合成实际请求及独立策略探测仍经过 C 与前置。这是资源服务器不可达，不是 Surge 控制器不可达。

旧 CLI 适配器在结果解析前扫描“无法连接”，因此把这条有请求 key 的结果错误分类为 `SURGE_UNREACHABLE`。针对真实脱敏输出的回归在修复前失败。

## 修复和边界

只对退出 0、恰好一行、以前述请求 key 加冒号开头的 `updateExternalResource` stdout，跳过通用控制连接文字匹配，交给原有严格资源解析器。非 `success` 仍抛出 `SURGE_COMMAND_FAILED`，不认为刷新成功，不重试。

stderr、真正控制器断连提示、其它 key、多行输出、其它原语继续保留原有拦截。命令白名单、入口、能力门槛均未放开。

## 验证

- 10 个真机错误文字样本（HTTP 错误、空响应、解析失败、重置、超时、连接失败）及 4 个控制连接边界回归。
- 类型检查通过。
- 首次 `npm run check` 默认并发在 5 个文件中出现 7 个 5 秒超时，因此该次未通过。
- 保持原超时值，以 Node 24.19.0、`vitest run --maxWorkers=2` 复核完整套件：**143 个测试文件通过；3989 项通过、1 项跳过**。
- 所有工作区构建通过；仓库扫描 598 个文件通过。

本修复尚未部署到产品应用。维护实测只用合成资料；测完已逐字恢复主配置及 6 个依赖，选择 REJECT，临时规则 0，自动重载关闭，临时服务和测试页面均已关闭。原始配置、资源地址、凭据与日志不随 PR 上传。
