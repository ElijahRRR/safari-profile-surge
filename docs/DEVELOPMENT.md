# 开发实施与验收

日期：2026-10-21。性质：开发任务书与验收约定（本文是任务书，不随实现改写；实现进度见 README「当前状态」，与本文的偏离见 docs/ARCHITECTURE.md §0，测试 Mac 实测见 docs/verification/）。

## 1. 目标与技术拆分

开发一个本机工具：Safari 扩展识别已绑定场景，通过本机服务让 Safari 采用环境指定代理；网页后台负责批量导入、配置和状态；Surge 负责网络转发。

建议采用 Swift 原生宿主/桥接、独立本机后台、TypeScript 网页和 Web Extension、SQLite 与 Keychain。后台具体语言可在检查团队与打包环境后确定；这不是已经锁定的现有工程结构。不要引入云数据库来存代理或账号信息。（实现按用户决定不使用 Keychain，秘密以明文保存在本机服务自己的 SQLite 中，见 docs/ARCHITECTURE.md §0「秘密的存放」。）

| 组件 | 职责 | 不负责 |
|---|---|---|
| Safari Web Extension | 弹窗、当前场景操作、受限登录页填充、请求当前状态 | 直接编辑 Surge、持有管理密钥、用网页推断可信场景 ID |
| 原生宿主/桥接 | 获取可信 profile 身份、核验消息、连接本机服务 | 根据窗口标题猜场景 |
| 本机后台 | 数据、唯一写入队列、凭据引用、导入、同步与激活事务 | 将文件写成功等同网络生效 |
| 网页后台 | 环境管理、差异、操作进度、实际出口与错误 | 自己成为第二套配置源 |
| Surge 适配层 | 检测版本能力、生成候选、定向更新、读回、组选择、精确连接处理 | 任意 shell 执行、修改无关配置 |

可按 apps/native、apps/web、extension、service、tests、docs 组织未来代码，不必为了结构先建立空壳项目。

## 2. 最小数据模型

| 实体 | 最小字段/约束 |
|---|---|
| Environment | 稳定 ID、展示名、站点、自动开订单/填充选项、revision |
| ProfileBinding | 原生 profile ID、environment ID、绑定状态；一对一约束 |
| ProxyRevision | 环境、代理版本、协议/地址/端口、凭据引用、前置引用、预期出口（可空）、实际节点名 |
| FrontProxy | 稳定 ID、Surge 节点引用、归属、依赖和验证状态 |
| Account | 环境关联、账号标识、登录凭据引用；与页面实际登录身份分开 |
| Deployment | 发布代数、工作配置身份、资源摘要、节点清单、部署状态 |
| ActiveRoute | 当前环境/版本、route_epoch、入口模式、实际组选择、最近验证 |
| Operation / Outbox | request_id 唯一、期望 revision、阶段、结果、重试/恢复所需引用 |
| ProbeResult | 代理预检或 Safari 实测、时间、出口、策略、连接关联、有效期 |

期望数据、任务入队在同一 SQLite 事务提交。Keychain 与 SQLite 不是真正的跨系统事务：先创建新秘密引用，再提交数据库引用；失败清理未被引用的凭据，不能用不存在的引用提交“可用”状态。旧凭据在回滚和旧连接不再需要后再清理。（不使用 Keychain 后，这个顺序在同一数据库中照旧保留，见 docs/ARCHITECTURE.md §0「秘密的存放」。）

desired、deployed、active 三个版本分别记录。没有部署或没有浏览器实测，不能把它们强行设成相同。

## 3. 通信与任务契约

详细接口以 [实时同步设计](../design/插件-网页后台-Surge实时同步设计.md) 为准。

- 插件通过 native messaging 请求/响应；宿主补充可信 profile 身份，后台验证其绑定，拒绝越过绑定修改其他环境。
- 网页使用回环 HTTP，认证、Host/Origin 检查和 CSRF 防护；状态用 SSE。普通网页不能靠访问 localhost 获得管理权限。
- 插件弹窗保存后查询 operation_id；打开期间短周期查询，关闭停止。扩展生命周期不能作为后台任务的生命周期。
- GPT/导入工具通过受限本地接口调用同一后台，不直接写配置或用命令行传密码。
- 修改携带 expected_revision 与唯一 request_id。重复请求返回原任务；冲突返回当前版本与脱敏差异。
- 202 表示受理。任务阶段建议：SAVED、VALIDATING、WAITING_DEPLOYMENT、DEPLOYING、DEPLOYED_UNVERIFIED、PREFLIGHT_OK、SAFARI_BLOCKED、VERIFY_ONLY、ACTIVE_VERIFIED、FAILED、ROLLING_BACK。
- SSE 带事件序号，断线补读或读取完整快照；旧 route_epoch 的检测结果不得覆盖新的活动环境。
- 后台重启先读 Surge 事实再恢复任务，不能重放所有写操作。超时是未知状态，不是直接重试的理由。

## 4. P0：先验证会决定架构的能力

这一阶段只用空白场景、测试域名与本地提供的测试代理，不导入买家凭据。记录当前配置与接管状态，准备精确回退；原始配置不可提交到仓库。

| 验证项 | 通过条件 | 不通过时 |
|---|---|---|
| Safari 精确进程归属 | Safari 实际连接命中特定路径，Chrome 和其他 WebKit 不命中；相关协议逐项检查 | 不扩成通用 WebKit 规则；停止宣称整个 Safari 可控 |
| 原生 profile ID | 在不同场景可靠区分，重启生命周期明确 | 不以场景名猜测；重新绑定机制先落地 |
| 固定配置日常切换 | A/B 切换配置身份不变，不重载主配置 | 不能以多配置切换替代 |
| 运行时入口四种模式 | NORMAL/BLOCKED/VERIFY_ONLY/ACTIVE 精确生效，操作顺序无误放行窗口 | 不后台重复 reload；明确产品能力受限 |
| 节点资源被自动重新读取 | 原子写入本地节点资源后不调用 `external-resource update`（文档：本地资源被跳过），Surge 在限定时间内自动重新读取；新成员可读可选，前置正确，保留旧成员/选择，其他资源不变 | 新数据保持待部署（WAITING_DEPLOYMENT）；不实现回环地址远端资源替代，也不自动全局重载 |
| 连接连续性 | 新增非活动环境不重置 Chrome 长连接，新短请求也正常，出口保持基线 | 不能称无中断发布 |
| 首请求与旧连接 | 先准备出口再加载业务页，旧环境后台及长连接不能继续错用出口 | 采用受控启动/关闭旧会话，写明限制 |

最低支持 Surge for Mac 6.10.0（构建 ≥ 12500、Controller 协议 ≥ 22）。design 中 6.5 的只读命令与离线语法证据（[调研记录](../design/固定工作配置-命名与更新机制.md)）只作历史记录，不作为 6.10 的证据，更不能当作上述 P0 已通过；按 6.10 官方文档与随包技能使用命令，偏离 design 之处见 [ARCHITECTURE §0](ARCHITECTURE.md)。

额外检查：本地 policy-path 是否真正重新读取；候选外部节点能否在不改变当前活动组的前提下独立预检；Surge 自动重载设置与原子替换行为；Surge 重启后临时规则生命周期。每项记录支持/不支持/待验证和实测依据。

## 5. P1：先实现离线控制核心

1. 定义数据模型、版本约束与错误类型；编写使用合成数据的测试。
2. CSV/XLSX/JSON 导入进入同一校验服务：禁止公式执行和外部链接，检查端口、协议、前置环路、重复 ID 与字段序列化。
3. 稳定命名、归属清单和差异生成；特殊凭据无法在当前 Surge 语法中安全表达时拒绝，不能拼接原始文本。
4. 生成候选文件、官方 CLI 校验、资源节点清单比对；候选文件不被激活。
5. SQLite Outbox、唯一写入者、版本冲突、幂等任务与断点恢复。
6. Surge 适配层区分文件发布、资源更新、主配置重载和组选择；不提供通用任意命令接口。

验收：坏配置不触碰活动文件；重复导入不重复创建节点；用户同时编辑不丢失覆盖；程序崩溃后根据实际状态恢复；所有日志不含凭据。

## 6. P2：完成发布与网络切换

P0 相应能力通过后，才连接真实 Surge：

1. 初始化备份与固定日常工作配置，一次创建 SFE-ROUTE；保留用户后续编辑。
2. 环境代理新版本原子写入受管理的本地节点资源，等待 Surge 自动重新读取（不调用 `external-resource update`：本地资源被跳过；P0 的 policy_path_reread 确认之前保持待部署）并读回；从不使用 update all 或重载兜底。
3. 活动环境切换先阻止 Safari 业务请求，处理确认属于 Safari 的旧连接，选择候选节点，开放检测，再由 Safari 验证。
4. 失败保留旧版本并按已验证路径回滚，不能回退 DIRECT 或其他买家出口。回滚未知时明确告警。
5. 普通模式撤销自己的入口继续整套原规则；不删除用户临时规则，不清空全部连接。

发布与路由是两个阶段。非当前环境的新节点即使已经部署，也不能为了预检改变当前 Safari 的选择；独立预检能力不足时保留待验证。

## 7. P3：接入插件与本机网页

- 网页列表显示环境、绑定、代理连接地址、前置、期望/已部署/活动版本、实际出口时间、错误与下一步。
- 插件默认展示当前可信场景的绑定；未绑定提供关联或新建，不能自动套同名环境。
- 插件编辑和网页编辑共享操作 ID 与版本；保存后关闭界面任务仍继续。
- 初次关联向导处理 Safari 扩展启用与网站权限。新场景默认关闭扩展（Apple：“By default, extensions are turned off for each new profile.”），每个场景都要用户自己启用，不能承诺替未来场景自动启用；网站授权自 Safari 17 起对所有场景共用（“that grants the extension access to the site across all profiles, private browsing, and browsing without a profile”），只需授权一次。默认场景可能拿不到场景 ID，环境只关联在已命名的场景中（docs/ARCHITECTURE.md §0.1）。
- 全局一个活动环境；焦点到 Chrome 不释放当前出口，多场景冲突不能争抢。
- 实际出口检测来自当前 Safari 场景。后台代理探针明确标为预检；不开 MITM 时不声称 Surge 看到了 HTTPS query 中的测试编号。

## 8. P4：订单与条件填充

只有绑定、出口和启动顺序可验证后，接入真实站点流程：

- 按环境站点打开或定位订单页；已有登录保留，不强制登出或重填。
- 只有允许的 HTTPS 登录页实际出现邮箱/密码字段才填充，检查顶层来源及表单目标，不向第三方 iframe 或相似域名填充。
- 不自动提交登录、验证码或二次验证，不执行下单。
- 编辑绑定账号不等于网页已切账号，显示配置身份和页面身份核验状态。
- 权限仅覆盖实际支持的站点，逐项申请；不以扩大到所有网站解决权限问题。

## 9. 测试、证据与交付

离线测试覆盖导入、配置注入防护、版本/幂等、回滚状态机、资源丢失、外部编辑和秘密脱敏。集成测试可用假的 Surge 适配器验证任务编排，但不能替代网络验收。

网络证据逐请求至少记录：测试编号、时间、场景代号、扩展/入口状态、期望节点、Surge 实际策略、实际出口、连接处理结果、配置身份、对照应用结果。代理入口与出口分开；HTTP/HTTPS 分开；DNS、IPv6、UDP/QUIC、WebSocket、WebRTC 与系统服务另列覆盖结果。

公开证据使用代号或脱敏字段，不公开原始请求头、浏览记录、账号与出口 IP。原始证据只在测试 Mac 限权存储；没有测试的行写“未验证”。

正式交付包括：源码、可安装且正常签名的宿主与扩展、网页后台、合成导入模板、最小配置差异、验收报告、可重复构建说明、停止服务/卸载/撤销本次规则的步骤。证书和既有规则不应被批量清理。清理临时测试服务，告知保留了哪些组件与开关。

开发完成条件是真实请求满足验收，不是 UI 变绿、HTTP 200、CLI success 或配置检查通过。
