# 验收报告模板

日期：2026-10-22（目标 Surge Mac 6.10.0 (12500)）；2026-10-31 按用户决定 D10 以回环资源四项（1.9–1.12）取代本地 policy-path 的两项，之后各节顺延。性质：测试 Mac 上的验收记录模板。**所有格子初始为「未验证」**；只有在测试 Mac 上实测、证据保存在本机限权目录之后才能改写。离线测试、UI 变绿、HTTP 200、CLI success 或配置检查通过都不能作为验收结果。

## 填写说明

- 已有的部分实测记录在 docs/verification/：[2026-10-24 增量](verification/2026-10-24-mac-p0-increment.md)（XCTest、P0 `instance`、`takeover_state_readable` 的 P0 结果通过但尚未在网页确认，`safari_process_attribution` 阻塞）、[2026-10-24 固定配置实测](verification/2026-10-24-fixed-profile-live.md)（自动重载关闭时本地 policy-path 文件不被重新读取，因此改为 D10）、[2026-10-25 回环资源主配置见证与失败矩阵](verification/2026-10-25-loopback-main-witness-matrix.md)、[2026-10-25 资源下载错误分类](verification/2026-10-25-resource-error-classification.md)。那些是增量观察，不是本模板的验收结论：本模板的格子只在完整验收时按下面的规则改写。

- 证据列按 docs/DEVELOPMENT.md §9：测试编号、时间、场景代号、扩展/入口状态、期望节点、Surge 实际策略、实际出口、连接处理结果、配置身份、对照应用结果。
- 公开报告只写代号与脱敏字段：场景写代号（例如 P0-测试、场景-A），出口写代号（例如 出口-A、与基线一致/不一致），**不写出口 IP、账号、原始请求头或浏览记录**。原始证据留在测试 Mac 的 `~/Library/Application Support/SafariProfileSurge/p0/<运行编号>/`。
- 测试编号使用 P0 测试页的测试编号或 `<运行编号>-<步骤>`；时间写本地时间与时区。
- 网络相关的表按协议分行（HTTP、HTTPS、HTTP/2、HTTP/3（QUIC）、WebSocket、WebRTC、DNS、IPv6、系统服务）；原生桥、场景 ID、签名等非网络能力按检查项分行。不适用的格子写「不适用」并说明原因，没有测的格子保持「未验证」。
- 能力的结论只以网页后台确认的能力记录为准：在每节末尾写确认时间与提议编号。
