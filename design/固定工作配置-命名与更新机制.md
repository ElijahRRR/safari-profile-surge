# 固定工作配置、命名与更新机制

日期：2026-10-21，Asia/Taipei。状态：调研与设计；本次没有修改、重载或切换运行中的 Surge 配置。本文修订此前“修改节点就默认重载主配置”的设计，与另外两份设计一起使用。

## 1. 固定一份日常工作配置

首次初始化时，备份本机当时实际使用的配置、关联的本地文件与相关运行开关，记录摘要；含凭据的备份限制访问。以该配置生成普通本地工作配置，建议名称为 `日常-Safari环境`。初次启用安排一次受控切换；此后普通上网和 Safari 环境都长期使用这一份配置。

- 原始备份用于恢复，不参与日常同步，也不被持续修改。
- 工作配置名称、路径和身份固定。环境 A/B 不是两份 Surge 配置，发布代数也不是新的可切换配置。
- 日常不得调用 `switch-profile`，不得启停 Surge/增强模式，不修改全局出站模式、不清理全部连接。
- 候选文件只做校验，绝不为了校验而切换成活动配置。配置文件移位时需保留或重新解析相对引用，不能只复制主文件就声称依赖齐全。
- 原有订阅、规则、模块和选择尽量原样保留；不把工作文件作为可被远端订阅整体覆盖的托管主配置。原有远端整体配置更新需比较并合并差异，不能覆盖本应用的内容。
- 以后用户在工作配置中修改日常规则，这份修改后的工作配置就是新基线。禁止每次从首次备份重新生成，丢掉后来修改。

同一路径原子替换文件也不等于无影响更新。要检查 Surge 的自动重载设置：写文件可能触发自动加载，不能先发布再假定仍有时间检查。完整检查、差异预览和变更许可必须在触碰活动文件之前完成。若原子重命名后文件监视行为不同，也须实测。

## 2. 名称、归属和最小结构

统一使用保留前缀 `SFE-`，不使用真实买家账号、密码、代理 IP 作为标识。名称限制为字母、数字和连字符；显示名可独立使用中文。首次扫描重名；发现非本应用拥有的同名对象时停止并处理，不能接管或覆盖。

| 对象 | 示例 | 含义与生命周期 |
|---|---|---|
| 固定出口选择组 | `SFE-ROUTE` | 所有环境共用，只创建一次；明确的首成员是 REJECT |
| 环境出口节点 | `SFE-N-E0001-US01-v003` | N=出口节点，E0001=稳定环境编号，US01=不含账号的创建时标签，v003=代理版本 |
| 专用前置节点（确实需要新建时） | `SFE-F-F0001` | F=前置；优先直接引用用户已有且经核对的固定节点，避免重复复制凭据 |
| 环境节点资源 | `sfe-nodes.list` | 只存本应用的环境出口节点，权限限制；新旧版本短期并存 |
| 主配置内受管理段 | `# SFE-BEGIN …` / `# SFE-END …` | 注释边界便于审阅；实际归属仍以数据库清单和内容摘要为准 |

界面显示“US-买家01 · E0001”，Surge 中可通过 E0001 找回关联；环境改名不更名节点或重建场景。代理参数变化才产生新节点版本。清理只删除归属清单中的对象，不能批量删除所有名字以 SFE 开头的对象。

每个环境新增一个节点，不默认新增一个策略组，不为每个 Amazon 域名生成规则。前置链逐节点明确配置为：本机 → 指定前置 → 环境 SOCKS5 → 网站。若引用用户已有前置组，组选择变化可能同时影响多个环境，必须记录依赖并重新验证；首版优先固定前置节点。

固定组的候选结构如下，仅为设计示意：

```ini
[Proxy Group]
SFE-ROUTE = select, REJECT, policy-path=sfe-nodes.list
```

外部节点由组导入，不假设它们能被其他规则/脚本按普通主配置节点名直接引用。当前版本必须验证组成员查询、选择、前置引用和检测路径。不能使用 `include-all-proxies`，避免把原有所有节点意外加入本组。

选择失效时 `select` 会使用首成员，所以明确保留 REJECT，不让丢失节点时自动选中其他买家出口。此规则也要求资源刷新后重新核对实际成员与选中成员。[官方 select 行为](https://manual.nssurge.com/policy-groups/select.html)

## 3. 已核对的能力与证据边界

本机只读结果：Surge **6.5.0 (10960)**；安装包自带的 Surge 操作技能和 CLI 帮助已读取。

| 项目 | 本次结果 | 能证明什么 |
|---|---|---|
| CLI 帮助 | 有 reload、switch-profile、external-resource list/update、--check | 这些是不同操作；存在指定资源更新入口 |
| external-resource list | 退出 0，JSON 返回 32 个资源定义 | 可枚举现有资源；未打印地址、密钥或资源内容 |
| dump temp-rule | 退出 0，规则列表为空 | 旧式临时规则读取可用；没有证明新增、删除、优先级及重载后行为 |
| 本地 policy-path 候选配置校验 | 退出 0、OK | 固定组、REJECT 首成员和本地资源引用语法接受 |
| 内联 SOCKS5 + underlying-proxy 候选配置校验 | 退出 0、OK | 示例前置引用与节点命名的配置语法接受 |

语法夹具使用 127.0.0.1:9 假节点、无密码，在临时目录检查后删除；未激活，未发代理请求。`--check` 成功不能证明外部文件全部节点已运行时加载，也不能证明代理连通、热更新或连接不重置。

官方资料区分了以下能力：

- `policy-path` 可引用文件或 URL；远端资源会缓存和定时更新，本地文件不适用下载间隔。无效/重名节点可能被跳过，因此刷新成功后必须逐项核对，不能仅看整体 OK。[外部节点](https://manual.nssurge.com/policy-groups/policy-including.html)
- Surge 官方团队曾明确说明：主配置 reload 不等于更新外置策略。此条用于区分操作，不作为本机 6.5 的无中断证据。[官方团队答复](https://community.nssurge.com/d/1287-surge4-for-mac)
- 最新 HTTP 外部资源接口标注 Mac 6.10+，并说明该下载接口跳过本地资源；外部节点增强查询标注 Mac 6.11+。本机不能照搬，优先使用实际存在的 CLI；CLI 对本地资源的更新行为仍待验证。[HTTP API](https://manual.nssurge.com/tools/http-api.html)
- `#!include` 混合普通行的最新语法标注 Mac 6.9+，多文件分段还可能使对应配置段在 UI 中只读。因此不在 6.5 上贸然拆散用户的全部原配置。[配置格式](https://manual.nssurge.com/profile/format.html)
- 模块不能用来添加普通节点和策略组。[模块限制](https://manual.nssurge.com/profile/module.html)

未找到官方承诺“同一主配置 reload 或任意外部资源刷新必定保留所有连接”。因此当前不提供零中断保证。

## 4. 不同修改采用不同生效方式

| 用户动作 | 文件/运行状态变更 | 生效策略 |
|---|---|---|
| 改备注、买家号、登录密码、显示名称 | 本地数据库/Keychain | 不触碰 Surge |
| 在已部署 A/B 之间切换 | SFE-ROUTE 的选择；必要的 Safari 入口状态 | 不切配置、不重写节点；处理 Safari 旧连接并检测出口 |
| 新增环境/改代理 IP、端口或代理密码 | 环境节点资源的新代数 | 优先只刷新该资源；通过版本与网络验证后才标为已部署 |
| 修改现有环境的前置引用 | 新版本出口节点 | 同上，验证完整代理链；不是只测 SOCKS5 入口可达 |
| 新增专用前置节点/组或改固定基础结构 | 固定工作配置受管理段 | 低频配置维护；校验并合并一次，按已验证的方式重载同一配置 |
| 删除环境 | 先解除活动使用与依赖，再移除节点 | 定向发布；不删当前连接还依赖的节点，不立刻反复清理 |
| 返回普通模式 | 移除本应用的 Safari 路由入口 | 继续原规则；不能把 SFE-ROUTE 改为 DIRECT 代替 |

**默认优先路线：固定主配置 + 固定组 + 独立环境节点资源 + 指定资源刷新。**本地文件优先，避免给含凭据节点列表增加网页下载入口。但“本地文件修改能否即时重新加载”是必须通过的能力门槛，尚未通过。

如果当前 CLI 跳过本地文件、不能正确更新成员或影响其他连接，不能悄悄退化成“每保存一次就重载主配置”。新版本保留为“已保存，待部署”。可以另测受保护的回环资源服务，但它增加了凭据读取边界，不能随便开放一个无需认证的 localhost 订阅地址；也不能假设 Surge 支持任意自定义鉴权头。未经验证不纳入首版承诺。

维护期重载同一配置是低频后备能力，不是零中断要求的替代品。若用户要求整个电脑持续联网，而本机测试发现它会打断其他应用，就不在使用中执行。批量导入一次发布，失效节点清理延后合批，减少结构变更次数。

## 5. 保存代理后的发布事务

1. 插件/网页保存期望版本，后台立即返回操作 ID。界面显示保存成功与同步进度，不显示新 IP 已使用。
2. 校验数据、前置引用、环路及版本冲突；在活动文件之外生成候选资源。分别检查完整候选配置及预期节点清单，不能只凭配置解析器跳过坏行后返回 OK。
3. 保留旧版本节点，添加带新版本号的节点，生成摘要。再次核对当前工作配置和资源均未被外部编辑。
4. 只有选定发布方式已通过能力/影响测试时才原子发布。按实际枚举到的资源 key 定向更新；禁止 update all，避免顺便更新用户的其他订阅、脚本和规则。
5. 读取资源错误、实际组成员和原选择。核对数量、唯一名称、版本和可获得的有效参数；查询能力不够时不能报完整读回成功，须在能力测试中解决。检测同一个 key 是否仍对应本应用资源，不能缓存旧 key 后盲用。
6. 非活动环境：在能够独立检测候选节点的前提下预检，成功成为下次可用。若当前版本只能借当前选择组测试，则延迟该预检至激活，显示“已部署，待网络验证”，不得改变当前使用者的出口来测试。
7. 活动环境：只有资源发布完成才进入 Safari 受控切换；阻断/处理旧连接、选择新版本、读回、Safari 实测出口。代理后台预检与浏览器实测分开记录。
8. 成功后提交已部署/活动版本，推送网页事件；插件读同一任务状态。旧节点留到安全清理窗口，避免成功后立即触发第二次资源发布。

数据库与外部文件不能做成一个真正的原子事务。记录每个发布阶段；超时先查询，不重复刷新。失败回滚到旧资源及原选择也必须走已验证发布路径，不能静默切回另一份配置或 DIRECT。

## 6. Safari 入口开关不能藏着主配置重载

在已验证的 Safari 精确进程入口之上，普通模式、阻断、仅检测、正常托管需要改变入口状态。不能只声称“切组不用 reload”，实际上每个状态又 reload 主配置。

优先验证本机技能列出的旧式临时规则新增/删除/修改命令，并核对实际优先级、精确作用范围、添加删除顺序、崩溃、Surge 重启和配置重载后的保留情况。最新文档中 Mac 6.9+ 的 `rule temp` 命令形式不能直接用于本机 6.5。[CLI 文档](https://manual.nssurge.com/tools/cli.html)

若采用临时规则，只能按本应用记录的准确规则逐条管理，禁止 flush-temp-rule；不能删除用户自己的临时规则。改变多条规则的过程不是原子操作，需保持已确认的阻断，避免先删除后添加造成放行窗口。规则顺序不能稳定实现时，此路线不通过。

在精确运行时入口切换未通过前，NORMAL/BLOCKED/VERIFY_ONLY/ACTIVE 只是逻辑设计，不宣称可交付。不能以后台反复重载主配置掩盖能力不足。Surge 重启后入口可能消失，也不能承诺永久防泄漏；控制器未完成对账时停止自动打开订单和填充。

## 7. 上线前必须测“联网是否被影响”

以下测试需实际发布动作，未在本次设计调研中执行：

| 变化 | Safari 检查 | 其他应用检查 | 配置/运行读回 |
|---|---|---|---|
| 只选择已有环境 | 新出口；旧 H2/WebSocket 连接按设计结束 | Chrome 长连接连续、同时新请求正常、出口保持 | 工作配置身份不变，仅专用组选择变化 |
| 新增非当前环境节点 | 当前活动出口与会话保持 | 连续连接与新请求均正常 | 新成员存在、旧成员/选择不丢失 |
| 更新当前节点参数 | 只有受控切换时结束 Safari 旧连接 | 不终止 Chrome/其他应用连接 | 资源新版本与活动新版本分别确认 |
| 返回原规则/进入托管 | 入口切换正确，无短暂误放行 | 不受 Safari 临时规则影响 | 原规则不被覆盖，无主配置重载 |
| 同一配置维护重载 | 请求成功率、连接重置、恢复时间 | 长连接、短请求、DNS、UDP 及其他应用观察 | 接管/系统代理/模式不变；记录是否重启引擎 |
| 资源坏行、缺失前置、下载失败、服务退出 | 不切到错误节点 | 原有正常连接保持 | 失败不冒充成功，不更新全部资源 |

同时记录请求时间、连接标识、错误/重置、延迟、Surge 实际策略、出口与配置摘要。外部站点偶发失败需与未执行变更时的对照比较，不能单凭一个失败断言 Surge 断网，也不能单凭一个 200 宣称无影响。DNS 缓存、旧连接复用和刷新后新建连接均需覆盖。

验收门槛：日常切环境不切配置；资源发布不影响非目标应用；若定向刷新达不到此要求，就保持待部署，不把“实时同步”和“零全局中断”写成已实现。
